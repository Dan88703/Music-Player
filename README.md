# my-music-player

Мой личный музыкальный плеер. Кидаю mp3 в папку, пушу, Vercel собирает сайт, слушаю по ссылке с телефона или ноута.

Стек: React, TypeScript, Vite. Бэкенда нет, всё статикой.

## Что умеет

- список треков с обложками и тегами (читаются прямо из файлов)
- поиск по названию, исполнителю, альбому
- shuffle, повтор (очередь / трек), перемотка, громкость
- запоминает последний трек и настройки
- работает с экрана блокировки и медиа-клавишами (Media Session API)
- нормально выглядит на телефоне

Хоткеи: `Space` пауза, `←/→` ±10 сек, `Shift+←/→` прошлый/следующий трек, `S` shuffle, `R` повтор, `M` звук, `/` поиск.

## Как работает

Vercel отдает только статику, сервера, который мог бы прочитать папку с музыкой, там нет. Поэтому перед сборкой запускается `scripts/generate-manifest.mjs`: он проходит по `public/music/`, вытаскивает теги и обложки и пишет все в `public/tracks.json`. Фронт просто грузит этот json.

```
public/music/                  музыка
scripts/generate-manifest.mjs  собирает tracks.json + covers/
src/hooks/usePlayer.ts         логика плеера (очередь, shuffle, repeat)
src/components/                UI
```

## Запуск

```bash
npm install
npm run dev
```

Музыку класть в `public/music/`, можно по папкам.

## Деплой

Пушу репо на GitHub, на vercel.com импортирую проект, всё. Настройки лежат в `vercel.json`. Новые песни = закинуть файлы и сделать `git push`.

## Если файлов много

GitHub не пускает файлы больше 100 МБ, поэтому большие треки можно держать в Vercel Blob / R2 и прописать ссылки в `remote-tracks.json` (пример в `remote-tracks.example.json`).

Ссылка на сайт публичная, так что никуда ее не выкладываю.
